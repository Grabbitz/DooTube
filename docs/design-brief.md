# DooTube — ข้อเสนอผลิตภัณฑ์ macOS

**สถานะ: บันทึกทิศทางที่ผู้สร้างยืนยันแล้ว พร้อมรายละเอียดที่ยังเป็นข้อเสนอ; เก็บไว้เป็นประวัติการออกแบบก่อนเริ่มพัฒนา**
การยืนยันรอบนี้ครอบคลุมความเรียบแบบ Mac และลำดับ Watch ก่อน Music เท่านั้น ไม่ใช่การอนุมัติหน้าตา ค่าเริ่มต้น API หรือสถาปัตยกรรมทั้งหมด
อ่านข้อจำกัดทางเทคนิคและแนวทางพิสูจน์ความเป็นไปได้ประกอบใน [Architecture](architecture.md)

## 1. เป้าหมายที่ยืนยันแล้ว
- แอป native macOS ที่ใช้ Rust โดยมุ่งให้การดู YouTube ลื่นไหล
- ใช้ Kaset ที่ติดตั้งอยู่เป็นจุดอ้างอิง ไม่ใช่ข้อกำหนดให้ลอกหน้าตา
- ตามการเปลี่ยนแปลงและฟีเจอร์ของ YouTube ได้ต่อเนื่อง
- YouTube Music มีรายละเอียดเพลงลึก และปรับแต่งการใช้งานได้มาก
- **ทิศทาง UI ที่ยืนยันใหม่:** “เรียบแบบ mac” — หน้าหลักเรียบง่ายแบบ Mac เก็บเครื่องมือขั้นสูงไว้ให้เปิดเมื่อจำเป็น
- **ลำดับที่ยืนยันใหม่:** “เอา youtube ให้ลื่นแล้วไปเน้นmusic” — พิสูจน์ playback ก่อน ส่งมอบ Watch ที่ลื่นสำหรับใช้ประจำวัน แล้วเน้นความลึกและการปรับแต่ง Music
- รอบเอกสารออกแบบเดิมเพิ่มเฉพาะเอกสาร; implementation ปัจจุบันและขอบเขตที่ทำแล้วดู [Implementation](implementation.md) และหลักฐานจริงดู [Verification](verification.md)

## 2. บริบท หลักฐาน และขอบเขตคำสัญญา
- ตรวจ bundle สาธารณะพบ Kaset **0.14.2 (27)**; ยังไม่ได้สังเกตหน้าต่างแอปจริง
- เอกสารรุ่นนี้ระบุทั้ง Music/YouTube, queue, lyrics, EQ, media keys, extensions และ AppleScript
- จึงไม่ควรเรียกสิ่งเหล่านี้ว่า “Kaset ไม่มี”; การไม่พบในเอกสารไม่ยืนยันว่าไม่มีฟีเจอร์
- แหล่งอ้างอิงตรงรุ่น: [README ที่ commit ของแอป](https://github.com/sozercan/kaset/blob/e8e2c1bf4fe339da6439456b92a8a1700f7439e6/README.md) และ [release v0.14.2](https://github.com/sozercan/kaset/releases/tag/v0.14.2)
- **Native Music catalog, lyrics, credits และ custom player controls เป็น UX ที่ต้องการ ไม่ใช่สิ่งที่ทำแล้วหรือสิ่งที่ official APIs รับประกันว่าจะให้ได้**
- ต้องพิสูจน์ช่องทางข้อมูล สิทธิ์ เงื่อนไขบริการ และ capability จริงก่อนผูกมัดขอบเขต; ไม่ตัดเป้าหมาย Music ทิ้งหากช่องทางแรกใช้ไม่ได้
- หากต้องใช้ source-native official player ให้คง UI/branding/controls ที่ผู้ให้บริการกำหนด ห้ามปิดบัง ครอบทับ หรือตัดออก
- ใช้ custom controls ได้เฉพาะเส้นทางที่อนุญาตและรองรับจริง; focus mode และ customization ต้องไม่ละเมิดขอบเขตนี้

## 3. งานหลักที่เสนอ ภายใต้ลำดับ Watch ก่อน Music ที่ยืนยันแล้ว
1. เปิดลิงก์หรือค้นหาวิดีโอ → เล่น → ปรับคุณภาพ/คำบรรยาย → ดูต่อโดยไม่หลงบริบท
2. เปิดเพลงหรืออัลบั้ม → จัดคิว → อ่านเนื้อเพลง/เครดิต → ฟังต่อขณะทำงาน
3. ย้ายไปค้นหรือเปิด Library ระหว่างเล่น โดยไม่เริ่ม session ใหม่โดยไม่ตั้งใจ
4. ปรับเสียงและพื้นที่ทำงานเมื่อจำเป็น ไม่ต้องตั้งค่าหลายหน้าก่อนเล่นครั้งแรก
- กลุ่มใช้งานที่เสนอ: ผู้ดูและผู้ฟังบน Mac ที่สลับสองกิจกรรม และผู้ฟังที่ต้องการข้อมูลเชิงลึก
- ลำดับ Watch ก่อน Music ยืนยันแล้ว; workflow รายละเอียดและกลุ่มย่อยข้างต้นยังเป็นข้อเสนอ ไม่มีผลวิจัยรองรับว่าผู้ใช้ทุกคนให้ค่าน้ำหนักเท่ากัน

## 4. โครงสร้างข้อมูล: Watch / Listen / Library
- Sidebar หลักสามปลายทาง: **ดู (Watch)**, **ฟัง (Listen)**, **คลัง (Library)**
- Watch รวมหน้าค้นพบ การติดตาม ดูภายหลัง และประวัติ เมื่อผู้ให้บริการอนุญาต
- Listen รวมเพลง อัลบั้ม ศิลปิน เพลย์ลิสต์ และการค้นพบเพลง ตามช่องทางที่พิสูจน์แล้ว
- Library รวมรายการที่บันทึก โดยมีตัวกรองวิดีโอ/เพลงและป้ายแหล่งที่มาชัดเจน
- Search มีขอบเขต “ทั้งหมด / YouTube / Music”; การเปลี่ยนขอบเขตไม่ทำให้ข้อความค้นหาหาย
- **มี playback session ที่ใช้งานอยู่เพียงหนึ่งเดียว** พร้อมคิว ตำแหน่ง และจุดเข้าถึงการควบคุมที่คงอยู่ข้ามหน้า
- การเปลี่ยนหน้า Watch ↔ Listen คือการนำทาง ไม่ใช่คำสั่งเปลี่ยนสื่อที่กำลังเล่น
- เมื่อเปิดดูหน้าอื่น ต้องคง official IFrame player ที่กำลังเล่นให้มองเห็นได้ในขนาดที่สอดคล้องกับข้อกำหนด ไม่ซ่อนหรือย้ายไปเล่นเบื้องหลังเพื่อรักษา session
- การฟังต่อเมื่อปิดหน้าต่างหรืออยู่เบื้องหลังเปิดได้เฉพาะเส้นทางที่ capability และนโยบายบริการอนุญาต; หากไม่อนุญาต ให้ pause และแสดงสถานะอย่างชัดเจน โดยเก็บคิวและตำแหน่งไว้
- การกดเล่นรายการใหม่จึงเปลี่ยน active item; แยกคำสั่ง “เล่นตอนนี้ / เล่นถัดไป / ต่อท้ายคิว”
- คิวระบุชนิดและ provider ของแต่ละรายการ; รายการที่เล่นไม่ได้ยังคงอยู่พร้อมเหตุผล
- “ค้นหาเวอร์ชันเพลง/วิดีโอที่เกี่ยวข้อง” ให้เลือกผลลัพธ์เอง ไม่รับประกันว่าเป็นแหล่งเดียวกัน
- ไม่สัญญา gapless, การสลับเพลงกับ MV แบบไร้รอยต่อ หรือ timestamp ที่เทียบกันตรงเสมอ

## 5. Watch: ให้ภาพมาก่อนเครื่องมือ
- พื้นที่กลางเป็นวิดีโอ; ชื่อ ช่อง และการกระทำหลักอยู่ใกล้ภาพ ไม่แย่งพื้นที่ด้วย dashboard
- UX ที่ต้องการ: play/pause, seek, เวลา, volume, captions, quality, fullscreen และ PiP ตาม capability และข้อกำหนด player
- แสดงคุณภาพที่เลือกกับคุณภาพที่เล่นจริงแยกกันเมื่อทราบ; Auto ไม่แสดงตัวเลขสมมติ
- Inspector ด้านข้าง **หนึ่งช่อง พับได้** สลับแท็บ **Queue / Chapters** เมื่อมีข้อมูล
- คำอธิบายและความคิดเห็นอยู่ในเนื้อหาหลักด้านล่าง ไม่เปิด sidebar เพิ่มอีกฝั่ง
- ข้อเสนอ focus mode: ซ่อนเฉพาะข้อมูลรองและ sidebar ของแอป โดยคง official player UI ที่ต้องแสดง
- เมื่อหน้าต่างแคบ ให้ inspector ใช้พื้นที่แทนเนื้อหารองชั่วคราว; ไม่บีบวิดีโอเหลือช่องเล็ก

## 6. Listen: เพลงและรายละเอียดที่อ่านต่อได้
- เป้าหมาย native Music UX นี้ขึ้นกับผลพิสูจน์ provider ไม่ใช่คำรับรองว่า official APIs มี catalog/lyrics/credits ครบ
- ส่วนหัวแสดง artwork, ชื่อเพลง, ศิลปิน, อัลบั้ม และสถานะการเล่น; รายการเพลงเน้นการสแกนเร็ว
- Persistent player ใช้ตำแหน่งเข้าถึงคำสั่งเดียวกับ Watch เท่าที่ player อนุญาต โดยไม่ซ่อน official UI
- Inspector เดียวสลับ **Queue / Lyrics / Details** ไม่เรียงสามคอลัมน์พร้อมกัน
- Lyrics มี timed/plain ตามข้อมูลจริงและสิทธิ์ใช้งาน; เลื่อนอ่านเองได้พร้อมปุ่มกลับไปบรรทัดปัจจุบัน
- หากไม่มี timing ให้บอกว่าเป็นเนื้อเพลงไม่ซิงก์; หากไม่มีเนื้อเพลงให้บอก unavailable ไม่สร้างข้อความแทน
- Details เรียงจากเครดิต/รุ่นของเพลง/แหล่งข้อมูล ไปสู่ source metadata และ audio path
- Queue ใช้รายการกระชับ รองรับหลายรายการและย้ายลำดับด้วยคีย์บอร์ด ไม่บังคับ drag
- เพลงเดียวกันหลายเวอร์ชันแสดงชื่อเวอร์ชันและรหัสแหล่งที่มา ไม่รวมอัตโนมัติเพียงเพราะชื่อเหมือนกัน

## 7. ทิศทางภาพ: เรียบแบบ Mac ยืนยันแล้ว รายละเอียดยังเป็นข้อเสนอ
- **ยืนยันแล้ว:** เรียบแบบ Mac โดยเครื่องมือขั้นสูงไม่แย่งพื้นที่การใช้งานหลัก
- “สงบ ชัดเจน แม่นยำ” เป็นหลักการที่สังเคราะห์จากทิศทางนี้ ไม่ใช่คำพูดตรงหรือบุคลิกแบรนด์ที่ผู้สร้างอนุมัติ
- รายละเอียดภาพ ธีม สี แบบอักษร และค่าเริ่มต้นด้านล่างยังเป็นข้อเสนอ
- ใช้ภาพวิดีโอและปกอัลบั้มสร้างเอกลักษณ์; ลดกรอบการ์ดซ้อนและเอฟเฟกต์ตกแต่งที่แย่งสมาธิ
- เสนอธีมตามระบบเป็นค่าเริ่มต้น พร้อม Light/Dark ที่เลือกค้างได้; ยังไม่ล็อกสีหรือแบบอักษรแบรนด์
- เสนอพื้นที่เนื้อหาอ่านง่ายกับ accent เดียวสำหรับสถานะสำคัญ ไม่ใช้สีเป็นช่องทางบอกสถานะเพียงอย่างเดียว
- เสนอ density แบบ Comfortable เป็นค่าเริ่มต้น; Compact ยังรักษาขนาดพื้นที่กดและข้อกำหนด player
- เสนอ inspector ปิดเมื่อเริ่มครั้งแรก และจำสถานะต่อ workspace โดยไม่เปลี่ยนเพลงที่เล่น
- Motion ใช้บอกความเปลี่ยนแปลงเท่านั้น; เคารพ Reduce Motion และ Reduce Transparency

## 8. การปรับแต่งแบบค่อยเปิดเผย
- ยืนยันหลักการให้เครื่องมือขั้นสูงอยู่เบื้องหลังการใช้งานเรียบง่าย; การแบ่งหมวดและตัวเลือกต่อไปนี้ยังเป็นข้อเสนอ ไม่ใช่รายการฟีเจอร์หรือค่าเริ่มต้นที่อนุมัติแล้ว
- **Basic**: appearance, language, ขนาดข้อความ, density, autoplay และพฤติกรรมเมื่อปิดหน้าต่าง โดยตัวเลือกเล่นต่อเมื่อปิดหน้าต่าง/เบื้องหลังเปิดได้เฉพาะเส้นทางที่ capability และนโยบายบริการอนุญาต; เส้นทางอื่นต้อง pause พร้อมสถานะชัดเจน
- ข้อเสนอค่าเริ่มต้น: ไม่เริ่มเล่นเองจากการเปิดแอป; รายการแนะนำยังไม่แทรกคิวจนกว่าจะเปิดใช้
- **Advanced**: queue rules, shortcut rebinding, layout presets และรายละเอียดแหล่งสื่อ
- Queue rules แยก append/replace, การเพิ่มรายการแนะนำ, จำนวนล่วงหน้า และพฤติกรรมเมื่อเจอรายการเล่นไม่ได้
- ทุกกฎมีตัวอย่างผลลัพธ์; การกู้คืนค่าเริ่มต้นจำกัดเฉพาะหมวด ไม่ล้างคลังหรือคิว
- Shortcut editor ตรวจคำสั่งชนกัน แจ้ง system-reserved shortcuts และไม่แทนที่เงียบ ๆ
- Presets ที่เสนอ: Focus Watch / Daily Listen / Audio Detail; เปลี่ยน layout ไม่เปลี่ยน provider หรือ account
- บันทึก preset แบบมีชื่อและคืนค่าก่อนหน้าได้; settings ที่ใช้ไม่ได้ให้บอกเหตุ ไม่แสดงเหมือนเปิดใช้งานแล้ว
- มี “ค้นหาการตั้งค่า” และชื่อคำสั่งคงที่; การปรับแต่งไม่ครอบทับ official player UI ที่ต้องแสดง

## 9. ข้อมูลเพลงและคุณภาพ: บอกเท่าที่รู้
- ข้อมูลที่ต้องการ: credits, album/version, release date, duration, provider ID และลิงก์ต้นฉบับ ตามที่เข้าถึงและใช้ได้
- แต่ละ field มี provenance: ผู้ให้บริการ/การวัดจาก pipeline/ผู้ใช้ พร้อมเวลาที่ตรวจหรืออัปเดตเมื่อมี
- แยก **ไม่มีให้เข้าถึง (Unavailable)** จาก **ยังไม่ทราบ (Unknown)** และจาก **กำลังโหลด**
- แยก **Source quality** เช่น codec/bitrate ที่รายงานได้ ออกจาก **Output format** ของเส้นทางเสียงบน Mac
- PCM sample rate/bit depth หลัง decode ไม่ใช่หลักฐานว่าไฟล์ต้นทางเป็น lossless
- Bitrate แบบแปรผันต้องระบุลักษณะค่า; ไม่เอาค่าสูงสุดหรือค่าจากตัวเลือกมาแสดงเป็นค่าที่กำลังเล่น
- ไม่สร้าง PCM stats, dynamic range, loudness หรือ “Hi-Res” badge โดยไม่มีข้อมูลวัด/หลักฐานที่ตรงความหมาย

## 10. Audio Lab — ข้อเสนอที่ต้องพิสูจน์ความเป็นไปได้
- เสนอ preamp และ parametric EQ พร้อม frequency/gain/Q, presets, bypass และช่องเปรียบเทียบ A/B
- แยกการเปิด Lab ออกจากการเปิด processing; ค่าเริ่มต้นที่เสนอคือ bypass และ preamp 0 dB
- แสดง headroom ที่ตั้งไว้กับ meter ที่วัดได้แยกกัน; หากวัดไม่ได้ให้บอก unknown ไม่แสดงไฟปลอม
- เตือนเมื่อการ boost เสี่ยง clipping และเสนอการลด preamp; ไม่เปลี่ยนระดับเสียงโดยไม่บอกผู้ใช้
- A/B เปรียบเทียบค่าประมวลผลบนสื่อเดียว ไม่สลับแหล่งเสียงแอบแฝง; ระบุหากยังไม่ได้ level-match
- Gate ตาม OS, output route, สิทธิ์ และการเข้าถึง audio pipeline ของ player จริงโดยไม่หลบ DRM
- ขอ permission เฉพาะเมื่อเปิดฟังก์ชันที่ต้องใช้ พร้อมบอกขอบเขตข้อมูลที่จับและวิธีปิด
- หากเข้าถึงเสียงที่ป้องกันไว้ไม่ได้ ให้ปิดเฉพาะ Lab พร้อมเหตุผล; การเล่นปกติไม่ถูกบังคับให้ขอสิทธิ์นี้
- EQ เปลี่ยนสมดุลเสียง ไม่เปลี่ยน lossy เป็น lossless และไม่รับประกันเสียงดีขึ้นสำหรับทุกคน

## 11. Focus, คีย์บอร์ด และภาษาไทย
- ลำดับ focus: navigation → search → เนื้อหาหลัก → player → inspector; กลับจุดเดิมเมื่อปิด inspector
- Play/pause ด้วย Space เฉพาะเมื่อไม่ได้พิมพ์หรือใช้ control ที่มีความหมายของ Space อยู่แล้ว
- มีเมนู native และ command search เป็นทางเข้าคำสั่ง; focus ring ชัด ไม่ซ่อน action ไว้เฉพาะ hover
- VoiceOver อ่านชื่อปุ่ม สถานะเล่น เวลา และการย้ายคิว; ไม่ประกาศเวลาใหม่ทุกวินาทีจนรบกวน
- ไทยต้องทดสอบสระ/วรรณยุกต์ไม่ถูกตัด การตัดคำ ชื่อยาว และข้อความไทยผสมอังกฤษในทุก density
- รองรับการขยายข้อความ contrast ที่เพียงพอ และสถานะที่อ่านได้โดยไม่พึ่งสีหรือ animation

## 12. สถานะที่ต้องออกแบบก่อนส่งพัฒนา
- **Default/Empty**: ค้นหาหรือเปิดลิงก์ได้ตาม capability; คิวว่างบอกวิธีเพิ่ม ไม่บังคับ sign-in สำหรับงานที่ไม่ต้องใช้
- **Loading**: รักษาโครงหน้ากับรายการเดิม; ระบุส่วนที่กำลังโหลด ไม่ใช้ spinner บังทั้งแอป
- **Buffering**: แยกจาก paused; คงเวลาและปุ่มยกเลิก/ลองใหม่ ไม่รีเซ็ตคิวหรือเล่นซ้ำเองอย่างไม่แจ้ง
- **Auth expired**: แจ้งให้เข้าสู่ระบบใหม่เฉพาะความสามารถที่ต้องใช้; คิวและรายการบันทึกไม่ถูกล้าง
- **Offline**: บอกเครือข่ายขาด พร้อมข้อมูลที่มีอยู่ในเครื่อง; ไม่สัญญาดาวน์โหลดหรือเล่น offline โดยยังไม่รองรับจริง
- **Restricted**: แสดงเหตุที่ทราบ เช่น ภูมิภาค/อายุ/สิทธิ์สมาชิก; ไม่เสนอหลบข้อจำกัดหรือเดาสาเหตุว่าแน่นอน
- **Provider change**: แจ้งฟังก์ชันที่ได้รับผลและสถานะ compatibility; ฟังก์ชันอื่นยังใช้ได้ตาม capability
- Source failure ต้องไม่ลบคลัง เปลี่ยน account ล้างคิว หรือเลือกเพลงอื่นแทนโดยเงียบ; retry มีขอบเขตและยกเลิกได้

## 13. ลำดับส่งมอบ: พิสูจน์ playback → Watch ใช้ประจำวัน → Music
- **ลำดับผลิตภัณฑ์ยืนยันแล้ว:** ทำ YouTube ให้ลื่นก่อน แล้วจึงให้น้ำหนักกับ Music depth/customization; ชื่อ phase และขอบเขตรายละเอียดด้านล่างยังเป็นข้อเสนอ
- **Playback proof ก่อน:** ทดลองเส้นทางเล่นที่อนุญาตบน native macOS shell/Rust ตรวจ controls, lifecycle/visibility และข้อจำกัดจริงก่อนผูกมัดการออกแบบ player
- **ตรวจ Music/EQ แต่เนิ่น ๆ แบบจำกัดขอบเขต:** สำรวจ catalog, lyrics, credits, authentication, playback/control path และ EQ บน player/OS/output route จริง รวม DRM, policy และ permission เพื่อไม่เลือก architecture ที่ปิดทาง Music ภายหลัง
- การสำรวจช่วงต้นต้องบันทึกสิ่งที่ทำได้ สิ่งที่ยังไม่ทราบ และข้อจำกัดใน [Architecture](architecture.md); **ไม่ต้องสำรวจ Music/EQ ให้เสร็จทั้งหมดก่อนเริ่มพัฒนา Watch** และไม่ใช่คำสั่งให้ส่งมอบ Music หรือ Audio Lab ก่อน
- **Watch daily core ที่เสนอ:** session เดียว, search/link opening, playback/seek/resize/fullscreen, captions/quality ตาม capability, keyboard และ error recovery; วัดความลื่นก่อนย้ายจุดเน้น
- **Music focus ถัดไปที่เสนอ:** native Listen, queue, lyrics, rich details/provenance, Library และ customization ตามช่องทางที่พิสูจน์แล้ว; เป้าหมายที่ติดข้อจำกัดต้องกลับมาขอการตัดสินใจ ไม่ตัดทิ้งเงียบ ๆ
- Advanced presets/rebinding และ Audio Lab ยังเป็นข้อเสนอ; ส่งมอบ Audio Lab ได้เมื่อผ่าน engineering/policy/permission gates เท่านั้น ไม่ใช่เงื่อนไขให้ Watch ต้องรอ
- แยก provider compatibility ออกจาก UI; Rust-native ไม่ได้แปลว่าต้องเขียน DRM/player ใหม่เอง
- ติดตาม release/provider changes, ทดสอบเส้นทางสำคัญด้วยข้อมูลที่ได้รับอนุญาต และแสดง compatibility notes
- ไม่รับประกันรองรับทุกฟีเจอร์ YouTube ในวันแรก; สิทธิ์ เงื่อนไขบริการ และความเข้ากันได้ต้องตรวจต่อเนื่อง

## 14. ทดลองว่า “ดีกว่า Kaset” อย่างไร
- **ยังไม่มีผล benchmark**: ให้เทียบ Kaset รุ่นที่ติดตั้งกับ prototype บน Mac/เครือข่าย/สื่อและสิทธิ์เดียวกัน
- วัด time-to-first-frame, buffering, dropped frames, CPU/memory และ input latency แบบหลายรอบ; รายงานความแปรปรวน
- ทดลองเปิดลิงก์ → คำบรรยาย → chapters, จัดคิว → lyrics → details และกู้คืน auth/offline โดยไม่สูญคิว
- เกณฑ์ที่เสนอ: งานหลักครบโดยไม่หลง focus/เปิดสอง session, คิวไม่สูญ, quality ไม่กล่าวอ้างเกินข้อมูล และใช้คีย์บอร์ด/VoiceOver ได้
- ตั้งเป้าตัวเลขหลังเก็บ baseline; ระบุข้อได้เปรียบเฉพาะด้านที่ทดลองพบ ไม่สรุปว่า Rust เร็วกว่าโดยตัวภาษา

### เกณฑ์ย้ายจุดเน้นจาก Watch ไป Music — ข้อเสนอรอยืนยัน
- ใช้งานหลักได้ต่อเนื่อง: ค้นหาและเปิดลิงก์ → play/pause → seek → resize/fullscreen โดยไม่สร้าง session ซ้อนหรือทำบริบทหาย
- ใช้ captions ได้เมื่อเส้นทางนั้นรองรับ; หากไม่รองรับต้องบอก capability ชัดเจน ไม่แสดงเหมือนทำงานแล้ว
- เมื่อ buffering, offline, auth หรือ provider error คิวต้องยังอยู่ พร้อมสถานะและทางกู้คืนที่ชัดเจน ไม่เปลี่ยนรายการเองเงียบ ๆ
- เทียบ UI lag/input latency, dropped frames และ CPU/memory **รวม WebKit helper processes** กับ Kaset ที่ติดตั้ง บน Mac/เครือข่าย/สื่อ/สิทธิ์เดียวกัน ใช้หลายรอบและรายงานความแปรปรวนตาม baseline ข้างต้น
- ใช้ผล Watch daily core และข้อจำกัดที่บันทึกไว้ตัดสินความพร้อมร่วมกับผู้สร้างก่อนย้ายจุดเน้นไป Music; เกณฑ์นี้ยังไม่ใช่ข้อรับรองว่าลื่นกว่า และไม่มี numeric budget ที่ผู้ใช้อนุมัติ ตัวเลขใน Architecture ยังเป็นข้อเสนอเพื่อวัด

## 15. การตัดสินใจของผู้สร้างที่ยังเปิดอยู่
1. รายละเอียดภาพ ธีม สี แบบอักษร และค่าเริ่มต้นใดเหมาะกับทิศทางเรียบแบบ Mac ที่ยืนยันแล้ว

3. เป้าหมาย macOS ขั้นต่ำและแนวทางเผยแพร่/อัปเดตที่ยอมรับได้ เพื่อกำหนดขอบเขต player และ permission ที่ทำได้จริง
